# LogiAI — 30-Day Roadmap

The 30-day plan has two goals: ship a credible AI-native logistics control tower and build practical TypeScript/Bun/Elysia + AI engineering depth.

## Phase 1 — Foundation

### Day 1 — Product and domain
- Finalize product scope and hero workflow.
- Define Party, Shipment, Carrier, Warehouse, Route, RouteStop and ShipmentEvent.
- Define sender/receiver as shipment relationships.

### Day 2 — Database model
- Set up PostgreSQL.
- Set up Bun and TypeScript.
- Set up Kysely and database types.
- Create entities and relationships.
- Configure Kysely migrations.
- Learn relational modeling, SQL and query design.

### Day 3 — Elysia foundation
- Create Elysia application.
- Configure application settings.
- Configure explicit dependency composition.
- Add health endpoint.
- Add Shipment API.
- Implement `GET /api/shipments`.
- Implement `GET /api/shipments/{id}` with sender, receiver, carrier and route.
- Implement shipment events endpoint.

### Day 4 — Development data
- Build deterministic seed generator.
- Generate realistic parties, carriers, warehouses, routes, shipments and events.
- Create deliberate failure scenarios.
- Create hero shipment `TRK-1829`.

### Day 5 — API quality
- Request/response Zod schemas.
- Runtime validation.
- Consistent errors and exception handling.
- Pagination.
- Filtering and sorting.
- Learn Elysia lifecycle hooks and request handling.

### Day 6 — TypeScript deep dive
- Interfaces, types and type composition.
- Generics and utility types.
- Discriminated unions.
- Type narrowing.
- Enums and literal types.
- Async/await and Promise behavior.
- Error handling.
- Node/Bun runtime fundamentals.

### Day 7 — Tests
- Unit-test domain services.
- Integration-test Kysely queries.
- API tests for Elysia routes.
- Test Zod validation and error contracts.
- Review Week 1 architecture.

## Phase 2 — Control Tower

### Day 8 — Shipment search
- Search by tracking/order number.
- Filter by status, carrier and risk level.
- Pagination.

### Day 9 — Risk engine

- Separate operational calculation from presentation.
- Add risk levels.

### Day 10 — Next.js control tower

- KPI cards.
- Shipment table.
- Loading/error/empty states.

### Day 11 — Shipment details

- Sender/receiver.
- Carrier.
- Route.

### Day 12 — Exceptions
- At-risk shipments.
- SLA breach views.
- Carrier and warehouse exception summaries.

### Day 13 — API and frontend integration

- Query caching.
- Pagination/filter state.
- Error contracts.

### Day 14 — Week 2 review
- Performance review.
- Inspect SQL generated by Kysely.
- Index important query paths.
- Refactor boundaries where necessary.

## Phase 3 — AI

### Day 15 — Groq integration

- Create AI client abstraction.
- Establish system prompt and domain context.

### Day 16 — Structured AI responses
- Define discriminated Zod response contracts.
- Validate model output.
- Handle invalid model output safely.
- Add retry/fallback behavior where appropriate.

### Day 17 — AI tool registry

- Implement `getShipment`.

### Day 18 — Investigation

- Gather shipment, event, carrier, route and warehouse evidence.
- Return structured risk analysis.

### Day 19 — Operational queries
- "What needs my attention?"
- "Which shipments are at risk?"
- "Which carrier is performing worst?"
- Add search and aggregation tools.

### Day 20 — Recommendations
- Generate recommended actions.
- Include evidence and expected impact.
- Keep actions proposed, not automatically executed.

### Day 21 — AI review
- Prompt quality.
- Tool selection.
- Failure handling.
- Token/cost awareness.
- Guard against unsupported claims.

## Interview learning checkpoints

Throughout the project, be able to explain:

- Why Elysia vs other TypeScript web frameworks.
- Bun runtime characteristics and when Node.js may be preferable.
- Elysia request lifecycle and hooks.
- Explicit dependency composition vs framework-managed dependency injection.
- TypeScript structural typing, generics and discriminated unions.
- Runtime validation with Zod vs compile-time TypeScript types.
- Async/await, Promises and concurrency.
- Kysely query construction and type safety.
- SQL joins, indexes and transaction boundaries.
- Repository and service boundaries.
- REST API design.
- SSE vs WebSockets.
- Background tasks/workers.
- Structured AI output and tool calling.
- Why the LLM should not directly access the database.
- Why deterministic risk scoring remains outside the LLM.
- Human-in-the-loop design for consequential actions.

## Definition of done

The MVP is complete when an operator can:

```text
Open Control Tower
      ↓
See high-risk shipments
      ↓
Open TRK-1829
      ↓
Ask why it is at risk
      ↓
AI gathers operational evidence
      ↓
Structured root-cause analysis
      ↓
AI recommends an action
      ↓
Operator approves
      ↓
Backend executes simulated action
      ↓
Audit trail is updated
      ↓
SSE updates shipment state
```
