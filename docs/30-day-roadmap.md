# LogiAI — 30-Day Roadmap

The 30-day plan is to ship a credible AI-native logistics control tower using the active Python/FastAPI backend and Next.js frontend. The previous Bun/Elysia/Kysely implementation is retained under `backend_bun/` for reference, not as the active service.

The roadmap is intentionally outcome-oriented. Detailed architecture and contracts live in `docs/architecture.md` and `docs/ai-contract.md`.

## Phase 1 — Foundation

### Day 1 — Product and domain

- Finalize product scope and hero workflow.
- Define Party, Shipment, Carrier, Warehouse, Route, RouteStop and ShipmentEvent.
- Define sender/receiver as shipment relationships.

### Day 2 — Database model

- Set up PostgreSQL.
- Use Python 3.15.0, FastAPI, Pydantic v2 and SQLAlchemy Core.
- Define SQLAlchemy Core table metadata matching the existing PostgreSQL schema.
- Configure asyncpg and Alembic migrations; inspect existing schema before altering it.
- Keep request, response, configuration and external/LLM payloads validated with Pydantic.
- Learn relational modeling, SQL and query design.

### Day 3 — FastAPI foundation

- Configure FastAPI lifespan and validated application settings.
- Wire async SQLAlchemy sessions through FastAPI dependencies.
- Add health endpoint and OpenAPI docs.
- Implement party and shipment API routes.
- Implement shipment listing, detail, status updates and event history.

### Day 4 — Development data

- Build deterministic seed generator.
- Generate realistic parties, carriers, warehouses, routes, shipments and events.
- Create deliberate failure scenarios.
- Create hero shipment `TRK-1829`.

### Day 5 — API quality

- Define Pydantic v2 request/response schemas.
- Add runtime validation and strict unknown-field handling where appropriate.
- Add consistent errors and exception handling.
- Add pagination, filtering and sorting.
- Learn FastAPI dependency injection, lifespan, exception handling and request lifecycle.

### Day 6 — TypeScript deep dive

- Interfaces, types and type composition.
- Generics and utility types.
- Discriminated unions.
- Type narrowing.
- Enums and literal types.
- Async/await and Promise behavior.
- Error handling.
- Python async/await, typing and asyncio fundamentals.

### Day 7 — Tests

- Unit-test domain services.
- Integration-test SQLAlchemy Core queries against PostgreSQL.
- API tests for FastAPI routes.
- Test runtime validation and error contracts.
- Review Week 1 architecture.

## Interview learning checkpoints

Throughout the project, be able to explain:

- FastAPI request lifecycle, dependencies and lifespan.
- Python typing, async/await and asyncio concurrency.
- Pydantic runtime validation vs Pyright static type checking.
- SQLAlchemy Core query construction and typed result mapping.
- Alembic migrations and safe schema evolution.
- SQL joins, indexes and transaction boundaries.
- Repository and service boundaries.
- REST API design.
- SSE vs WebSockets.
- Background tasks/workers.
- Structured AI output and tool calling.
- Why the LLM should not directly access the database.
- Why deterministic risk scoring remains outside the LLM.
- Human-in-the-loop design for consequential actions.

## Definition of done

The MVP is complete when an operator can:

```text
Open Control Tower
      ↓
See high-risk shipments
      ↓
Open TRK-1829
      ↓
Ask why it is at risk
      ↓
AI gathers operational evidence
      ↓
Structured root-cause analysis
      ↓
AI recommends an action
      ↓
Operator approves
      ↓
Backend executes simulated action
      ↓
Audit trail is updated
      ↓
SSE updates shipment state
```
