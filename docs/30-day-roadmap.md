# LogiAI — 30-Day Roadmap

The 30-day plan has two goals: ship a credible AI-native logistics control tower and build practical Python/FastAPI + AI engineering depth for interviews.

## Phase 1 — Foundation

### Day 1 — Product and domain
- Finalize product scope and hero workflow.
- Define Party, Shipment, Carrier, Warehouse, Route, RouteStop and ShipmentEvent.
- Define sender/receiver as shipment relationships.

### Day 2 — Database model
- Set up PostgreSQL.
- Set up Python environment with `uv`.
- Set up SQLAlchemy 2.x and Alembic.
- Create entities and relationships.
- Configure migrations.
- Learn SQLAlchemy relationships and SQL basics.

### Day 3 — FastAPI foundation
- Create FastAPI application.
- Learn Python typing, Pydantic and async/await.
- Configure application settings.
- Configure FastAPI dependency injection.
- Add health endpoint.
- Add Shipment API.
- Implement `GET /api/shipments`.
- Implement `GET /api/shipments/{id}` with sender, receiver, carrier and route.
- Implement shipment events endpoint.

### Day 4 — Development data
- Build deterministic seed generator.
- Generate realistic parties, carriers, warehouses, routes, shipments and events.
- Create deliberate failure scenarios.
- Create hero shipment `TRK-1829`.

### Day 5 — API quality
- Request/response Pydantic schemas.
- Validation.
- Consistent errors and exception handling.
- Pagination.
- Filtering and sorting.
- Learn FastAPI middleware and dependency patterns.

### Day 6 — Python deep dive
- Classes and dataclasses.
- Type hints and generics.
- Protocols and interfaces by convention.
- `Optional`, unions and modern Python typing.
- Enums.
- Pattern matching.
- Iterables, generators and comprehensions.
- Async/await and concurrency fundamentals.

### Day 7 — Tests
- Unit-test domain services.
- Integration-test SQLAlchemy queries.
- API tests with pytest and FastAPI test clients.
- Review Week 1 architecture.

## Phase 2 — Control Tower

### Day 8 — Shipment search
- Search by tracking/order number.
- Filter by status, carrier and risk level.
- Pagination.

### Day 9 — Risk engine
- Implement deterministic risk scoring.
- Separate operational calculation from presentation.
- Add risk levels.

### Day 10 — Next.js control tower
- Dashboard shell.
- KPI cards.
- Shipment table.
- Loading/error/empty states.

### Day 11 — Shipment details
- Shipment summary.
- Sender/receiver.
- Carrier.
- Route.
- Risk score.
- Event timeline.

### Day 12 — Exceptions
- At-risk shipments.
- SLA breach views.
- Carrier and warehouse exception summaries.

### Day 13 — API and frontend integration
- TanStack Query.
- Query caching.
- Pagination/filter state.
- Error contracts.

### Day 14 — Week 2 review
- Performance review.
- SQL generated by SQLAlchemy.
- Index important query paths.
- Refactor boundaries where necessary.

## Phase 3 — AI

### Day 15 — Groq integration
- Add secure server-side Groq configuration.
- Create AI client abstraction.
- Establish system prompt and domain context.

### Day 16 — Structured AI responses
- Define discriminated Pydantic response contracts.
- Validate model output.
- Handle invalid model output safely.
- Add retry/fallback behavior where appropriate.

### Day 17 — AI tool registry
- Define tool contracts.
- Implement `getShipment`.
- Implement `getShipmentEvents`.

### Day 18 — Investigation
- Implement "Why is this shipment delayed?".
- Gather shipment, event, carrier, route and warehouse evidence.
- Return structured risk analysis.

### Day 19 — Operational queries
- "What needs my attention?"
- "Which shipments are at risk?"
- "Which carrier is performing worst?"
- Add search and aggregation tools.

### Day 20 — Recommendations
- Generate recommended actions.
- Include evidence and expected impact.
- Keep actions proposed, not automatically executed.

### Day 21 — AI review
- Prompt quality.
- Tool selection.
- Failure handling.
- Token/cost awareness.
- Guard against unsupported claims.

## Phase 4 — Realtime and Actions

### Day 22 — SSE
- Create FastAPI SSE endpoint.
- Build event publisher abstraction.
- Connect Next.js client.

### Day 23 — Event simulator
- Simulate shipment state transitions.
- Publish events.
- Update control tower without refresh.

### Day 24 — Action domain
- Define AIAction.
- Add proposed/approved/rejected/executing/completed/failed states.

### Day 25 — Human approval
- Action review UI.
- Approve/reject APIs.
- Authorization boundary.

### Day 26 — Action execution
- Implement simulated reroute.
- Implement notify-customer simulation.
- Persist action results.

### Day 27 — Audit trail
- Record AI recommendation, evidence, approval and execution result.
- Add action history to shipment details.

## Phase 5 — Polish and interview readiness

### Day 28 — Testing and reliability
- Unit tests.
- Integration tests.
- AI contract tests with mocked model responses.
- Failure scenarios.

### Day 29 — Observability and performance
- Structured logging.
- Correlation IDs.
- SQLAlchemy query review.
- API performance.
- AI latency/error metrics.

### Day 30 — Demo and deployment
- Dockerize frontend/backend.
- Production configuration.
- Final UX polish.
- Record a complete hero-scenario demo.
- Update README and architecture documentation.
- Prepare interview talking points.

## Interview learning checkpoints

Throughout the project, be able to explain:

- Why FastAPI vs other Python web frameworks.
- FastAPI dependency injection.
- ASGI and the request lifecycle.
- `async`/`await` and concurrency.
- Pydantic validation and serialization.
- Python typing and protocols.
- SQLAlchemy sessions and transaction boundaries.
- How SQLAlchemy translates ORM expressions to SQL.
- Lazy vs eager loading.
- Unit of work and session lifecycle.
- REST API design.
- SSE vs WebSockets.
- Background tasks/workers.
- Structured AI output and tool calling.
- Why the LLM should not directly access the database.
- Why deterministic risk scoring remains outside the LLM.
- Human-in-the-loop design for consequential actions.

## Definition of done

The MVP is complete when an operator can:

```text
Open Control Tower
      ↓
See high-risk shipments
      ↓
Open TRK-1829
      ↓
Ask why it is at risk
      ↓
AI gathers operational evidence
      ↓
Structured root-cause analysis
      ↓
AI recommends an action
      ↓
Operator approves
      ↓
Backend executes simulated action
      ↓
Audit trail is updated
      ↓
SSE updates shipment state
```
